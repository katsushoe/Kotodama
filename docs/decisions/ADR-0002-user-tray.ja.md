# ADR-0002: ユーザー権限でのトレイ常駐

Status: Accepted (2026-10-25、ユーザー指示)

## Context

個人PCで利用するKotodamaをWindowsサービスとして更新すると管理者権限が必要になる。
利用者はユーザー権限での起動、トレイ常駐、保存先への書き込みを希望した。
設定の唯一の正本は引き続き `C:\Kotodama\config\kotodama.json` とする。

## Decision

`Kotodama.Tray.exe` が同一プロセスで既存HTTPホストを実行する。ユーザー単位MSIが
HKCU Runへログイン時起動を登録し、ユーザーPATHとクライアント接続を構成する。
トレイは状態表示、設定とログの表示、再起動、終了を提供する。再起動時は設定を読み直す。
`--stop` は同一セッションの名前付きイベントで正常終了を要求する。
CLIのHTTPサーバー起動と業務コマンドのHTTP接続は保持する。

## 代替案と不採用理由

- Windowsサービス維持: ログイン前の稼働は可能だが、個人用途の更新に管理者権限が必要。
- 別ユーザープロファイルへ保存: ユーザー指定の唯一の設定パスと一致しない。

## 影響範囲・運用条件

トレイ、MSI、移行スクリプト、インストール・運用文書へ反映する。
ログイン前・ログアウト後は稼働しない。同一セッションの二重起動を抑止する。
既存per-machine MSIからの移行は旧MSIを管理者権限で削除してから行う。
旧版と新しいper-user MSIは別UpgradeCodeとし、異なるスコープの同時所有を避ける。
移行後の更新・削除は通常ユーザー権限で行う。設定ファイルと非空のDBディレクトリは保持する。

## セキュリティ条件

初回移行だけ管理者が対象ユーザーSIDへ保存先の変更権限を付与する。
管理者とSYSTEMの権限を保持し、ルートのグループ向け広範な書き込み権限を除く。
トレイは昇格せず起動する。HTTPは既存のloopback制限と認証設定を維持する。
複数ユーザーで同じ固定保存先を使う運用は想定しない。

## 実装・検証・利用者文書

トレイのビルド、MSI構造とパーサー検証、通常権限のファイル書き込み、
MCP接続・利用ログ・DB整合性を確認する。インストール・運用手順から本ADRを参照する。
