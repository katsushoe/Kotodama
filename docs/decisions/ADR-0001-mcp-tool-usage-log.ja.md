# ADR-0001: MCP Tool利用ログ

- Status: Accepted
- Date: 2026-10-23

## Context

Kotodamaの利用頻度と応答時間を後から調べられるようにする。一方、知識DBは会話ログの保存場所ではなく、利用者の入力・Tool応答を記録すると内容や個人情報が残る。

## Decision

すべてのMCP `tools/call`を共通Request Filterで計測し、専用表`mcp_tool_usage_log`へ1呼び出し1行を追加する。列は`tool_name`、UTCの`started_at`、`duration_ms`、`outcome`に限定する。引数、応答本文、利用者・クライアント識別子は保存しない。

`outcome`はMCP境界の結果を表す。非エラー応答は`success`、MCPエラーまたは例外は`error`、キャンセルは`cancelled`とする。Tool内の業務上の受理・拒否までは判定しない。記録は呼び出し処理後にベストエフォートで行い、DB書込み失敗が元のTool応答を変えないようにする。

既存DBでは通常の起動時スキーマ初期化で表と索引を追加する。保持期間は自動設定せず、自動削除もしない。削除は利用者がDBを管理する。

## Alternatives

- Knowledge GraphのEventとして記録: 業務知識と運用計測が混在するため採用しない。
- 通常のテキストログへ記録: 呼び出しごとの集計・期間検索が難しく、誤って引数を出力する危険もあるため採用しない。
- 入力と応答を含む監査ログ: 今回の利用頻度測定には不要な内容を永続化するため採用しない。

## Consequences and operations

- MCP Tool呼び出しごとにSQLiteへ小さな書込みが発生する。
- 記録障害時はアプリケーションログへ警告を出し、Tool応答は維持する。
- 保持期間を設けないためDBは増加する。DBとBackupのアクセス制御を維持し、必要な保持期間を決めた後に別途整理する。
- 実装、DB列、プライバシー条件、運用手順を統合テストと利用者文書で確認する。
